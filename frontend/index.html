Operating Systems: Multithreading & POSIX Threads

How Thread Factory implements core OS concurrency principles

1. pthread_create()

Worker Thread Pool

POSIX threads (pthreads) represent independent execution contexts that share the same memory space. In this project, a pool of N worker threads is spawned at startup and kept ready in memory.

pthread_create(&worker->tid, NULL, worker_routine, worker);
2. pthread_mutex_t

Mutual Exclusion (Mutex)

The Job Queue is a shared critical section. Without a mutex, multiple threads checking queue_pop() simultaneously would suffer race conditions and corrupt memory. The mutex guarantees atomic queue access.

pthread_mutex_lock(&sim_mutex);
Job j = queue_pop(&queue);
pthread_mutex_unlock(&sim_mutex);
3. pthread_cond_t

Condition Variables

Instead of wasteful CPU spinning (busy-waiting) when the queue is empty, idle worker threads sleep using pthread_cond_wait(). When a new job arrives, pthread_cond_signal() wakes an idle worker instantly.

pthread_cond_wait(&queue_cv, &sim_mutex); // Sleep
pthread_cond_signal(&queue_cv);          // Wake up
4. Amdahl's Law

Sequential vs. Concurrent

Sequential processing executes tasks one after another: \(T_{seq} = \sum t_i\). Concurrent processing runs independent jobs in parallel across multiple CPU cores, yielding a theoretical speedup factor: \(Speedup = \frac{T_{seq}}{T_{wall}}\).
